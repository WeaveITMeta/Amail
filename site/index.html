    How it works

    From MX record to approved reply, in six steps.

    The same reference path the open-source library documents. Durable at every hop, so a crashed worker never sends twice. Agents can also run a complete business pipeline by connecting tools over MCP, with durable records and a human quality gate at the checkpoints you configure. Read how MCP pipelines work.

    1. 1

      Mail lands at SES

      Your MX points at Amazon SES inbound. Cloudflare hosts the DNS: MX, Easy DKIM, MAIL FROM, and DMARC.

      MX 10 inbound-smtp.<region>.amazonaws.com
    2. 2

      Stored, not streamed

      The raw message is written to S3. The wake carries only a pointer to that object, never the body.

      s3://inbound/raw/<message-id>
    3. 3

      Claimed exactly once

      An append-only handled key is written before parsing. A duplicate wake stops right there.

      duplicate_ignored
    4. 4

      The right robot clocks in

      The recipient address picks the role. The robot loads its role skill from the catalog, then reads that one object.

      Job/support/SKILL.md
    5. 5

      Triage, then a draft

      Every message gets an internal report. When it helps, a draft. A draft is never a send.

      pending_approval
    6. 6

      A human says go

      You approve the exact rendered email. A separate send identity calls SES. Threading headers stay intact.

      approved → ses:SendEmail

    Safe by default

    Cute robots. Serious guardrails.

    Automation that answers your customers has to be boring in exactly the right places. These defaults ship on.

    • Kill switch ships on. Flip it and every send path stops, including ones a person already approved.
    • Human approval by default. Approval binds to a SHA-256 digest of the exact message. A chat that says "approved" sends nothing.
    • Split identities. The robot can read one object. It cannot call SES send. A prompt injection has nothing to steal.
    • Mail is data, not orders. Instructions inside an email never become policy.
    • Suppression first. Opt-outs, bounces, tests, and no-reply senders are dropped before any draft is written.
    • DMARC-checked replies. Replies go to the header From only when DMARC passed for it.
